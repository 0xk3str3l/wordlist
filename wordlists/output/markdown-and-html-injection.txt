# category: output / markdown-and-html-injection
# purpose: output-channel payloads — strings a model may emit (or be made to
#          emit) that break the renderer that displays them. The input filter
#          passes them because they are not "instructions"; the damage happens
#          downstream, when a chat UI, a docs page, or an agent log renders the
#          model's answer as HTML/Markdown. This is the output side of the
#          trust boundary (OWASP LLM05 — Improper Output Handling).
# use: test the *rendering* layer: does the app escape model output before it
#      reaches a browser, a markdown renderer, a terminal, or a CSV import?
#      Run these through the model (they need not "succeed") and assert the
#      output is escaped or neutralized on the way out.
# owasp: LLM05
# source-level: publicly documented XSS / markdown-injection vectors and the
#               OWASP LLM05 "improper output handling" guidance. Generic
#               payloads (alert(1), example.invalid) — no live target.
# defense: treat every model output as untrusted input for the *next* system.
#          HTML-escape or sanitize on render, use a safe markdown renderer with
#          raw-HTML disabled, never eval model text, and strip dangerous URL
#          schemes (javascript:, data:, vbscript:) from links.
